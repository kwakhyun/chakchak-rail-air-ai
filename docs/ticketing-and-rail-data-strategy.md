# 철도 데이터·항공/철도 예매 연계 전략

검토일: 2026-08-05

## 결론

착착은 직접 결제·발권 사업자가 아니라 **연결 위험을 계산하고 공식 예매 채널까지 안전하게 인계하는 서비스**로 운영한다. 현재 대회 제출 단계에서는 이 경계가 가장 현실적이고 신뢰도도 높다.

철도 시간표와 검증 데이터는 다음 우선순위로 사용한다.

1. 한국철도공사 `열차운행정보` 직접 API로 운행일·열차 시종착 운행계획 검증
2. 국토교통부 TAGO 열차정보로 승객 구간 시간표·운임 조회
3. 마지막 정상 응답
4. 서버에 버전으로 보관한 시연용 기준 시간표

2026-08-05 활용신청 자동승인과 키 전송 동의를 확인해 `KORAIL_OPEN_API_ENABLED=true`로 활성화했다. 실호출은 HTTP 200·결과코드 0이었고, 2026-08-12 전체 운행계획 369건을 확인했다.

## 철도 데이터 판단

- [한국철도공사 열차운행정보](https://www.data.go.kr/data/15125762/openapi.do)는 운행일자, 열차번호, 출·도착역, 계획 출·도착일시를 제공한다.
- 운행계획의 출·도착역은 열차 전체 운행의 시종착역이다. 서울–전주 같은 중간 정차구간 시간표를 그대로 대체하지 않으며, 해당 날짜에 운행하는 열차와 전체 운행계획을 검증하는 근거로 사용한다.
- 계획 데이터는 과거 3개월부터 미래 1개월 범위이며, 실제 운행정보는 전일까지 제공된다.
- [TAGO 열차정보](https://www.data.go.kr/data/15098552/openapi.do)는 KTX를 포함한 출·도착지 기준 시간표와 운임을 제공하지만 좌석·예매·실시간 지연 데이터는 아니다.
- 두 데이터 모두 이용허락범위 제한 없음으로 표시되지만, 착착은 원본 응답·확인시각·출처·유효일을 함께 저장하고 오래된 값을 실시간으로 표현하지 않는다.

서버 스냅샷은 장애 복구용이다. 현재 스냅샷은 `authoritative: false`이며 2026-08-12 서울–전주 시연 기준값이다. 다른 날짜의 실제 운행을 보장하지 않고 항상 코레일 최종 확인 문구를 함께 표시한다.

## 철도 승차권

공공데이터포털에서 확인되는 공개 API는 운행계획·운행정보·승차권 진위확인이지 좌석 조회·예약·결제 API가 아니다. 승차권 진위확인 API도 이용 완료 후 확인 용도이므로 예매에 사용할 수 없다.

따라서 현재 구현 범위는 다음과 같다.

- 착착: 안전 후보, 계획시각, 예상 운임, 추천 이유 제공
- 코레일 공식 채널: 실제 운행, 좌석, 최종 운임, 할인, 예매·변경·환불
- 화면 행동: `코레일에서 좌석 확인` 또는 `공식 채널에서 예매`

기관 협약으로 코레일톡 딥링크·좌석·발권 인터페이스가 제공되면 추천한 열차 식별자를 전달하는 단계로 확장한다. 공개되지 않은 내부 예약 주소를 추측하거나 화면을 자동 조작하지 않는다.

## 항공권

현재 인천공항 공공데이터는 도착 예정·변경시각, 터미널, 게이트, 수하물 수취대와 운항상태를 제공한다. 운임·좌석·판매 가능 여부·예약·발권은 제공하지 않는다.

항공 정보·예매는 세 단계로 나눈다.

1. 현재: 항공편 도착·변경 정보와 공식 항공사 예약/관리 화면 연결
2. 확장: Amadeus `Flight Offers Search`와 `Flight Offers Price`로 판매 가능한 항공편·가격·수하물 조건 표시
3. 상용화: `Flight Create Orders`와 발권 대행사 계약, 결제·환불·개인정보·여행업 관련 요건을 갖춘 뒤 실제 예약

Amadeus 시험환경 값은 실제 판매값으로 표시하지 않는다. 운영 예약은 발권 대행사 계약과 운영계정 승인이 필요하므로 해커톤 시연에서는 공식 항공사 연결이 적절하다.

## 사용자 문구 원칙

- `34,600원 예상` — 실시간 확정 운임이 아님
- `코레일에서 좌석 확인` — 좌석을 착착이 보장하지 않음
- `항공사에서 예약 확인` — 항공권 변경을 착착이 실행하지 않음
- `시연용 기준 시간표` — 스냅샷을 실시간으로 오인하지 않음
