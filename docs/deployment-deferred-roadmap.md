# 실제 배포 후순위 결정과 전환 조건

## 현재 결정

참가신청 필수서류에는 GitHub 저장소나 배포 URL 제출 요구가 확인되지 않았다. 따라서 2026-08-05 14:00 제출 전에는 아래 순서로 집중한다.

1. 참가신청서 p.4 문안 가독성
2. p.5 추가서류 캡처와 캡션
3. HWP 원본의 서명·동의·개인정보·페이지 배치
4. 한컴오피스 뷰어 최종 확인
5. 제출 메일과 첨부파일 열림 확인

관리형 PostgreSQL과 HTTPS 호스팅은 **제출 서류의 필수 조건이 아니므로 현재 합격 가능성을 직접 높이지 않는다.** 로컬 데모·스크린샷·자동 테스트에는 필수도 아니다.

## 왜 나중에는 필요한가

| 요소 | 실제 서비스에서 필요한 이유 | 지금 미뤄도 되는 이유 |
|---|---|---|
| 관리형 PostgreSQL | 여러 참여자의 예측 잠금·동의 이력·탑승 결과를 동시에 보관하고 트랜잭션, 백업, 복구, 접근통제를 제공 | 현재 실제 파일럿 완료 0건이며 로컬 파일 저장으로 기능 시연과 테스트 가능 |
| HTTPS 호스팅 | 이동 중 개인정보·동의·익명 토큰 전송을 암호화하고 브라우저 보안 기능과 외부 콜백을 안정적으로 사용 | 제출은 로컬 캡처와 HWP이며 외부 참여자가 접속하지 않음 |
| 상시 서버 | 공공 API 갱신, 예측 잠금, 현장 결과 입력, 운영 로그를 여러 기기에서 사용 | 심사 전에는 한 대의 로컬 데모로 전체 흐름 재현 가능 |
| 자동 백업·모니터링 | 파일럿 자료 손실과 장애를 방지하고 감사 가능성을 확보 | 실제 참여자료를 수집하지 않는 동안 운영 위험이 없음 |

## 배포를 다시 P0로 올리는 조건

다음 중 하나가 생기면 배포를 즉시 우선순위로 올린다.

- 운영사무국이 예선 평가에 접속 가능한 URL을 요구
- 발표자가 아닌 심사위원이 직접 서비스를 조작해야 함
- 실제 파일럿 참여자 모집을 시작
- 기관 원장 대조나 다기기 현장 기록을 시작
- 공항·코레일 멘토가 실데이터 운영 검증을 요청
