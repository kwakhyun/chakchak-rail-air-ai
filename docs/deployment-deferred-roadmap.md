# 공개 데모 배포 현황과 운영 전환 조건

## 현재 상태

2026-08-05 제출 전에는 참가신청서 완성과 로컬 데모 검증을 우선했고, 예선 이후 포트폴리오 재구성 과정에서 공개 데모를 배포했다.

- 공개 데모: <https://chakchak-rail-air-2026.khyun97.chatgpt.site/>
- 배포 범위: 서비스 UI, 발표 화면, 데이터 융합 조회, 자체 모델 추론, AI 안내
- 제한 범위: 실제 이동 기록 등록·관측·철회와 파일럿 운영자 API는 공개 배포판에서 차단
- 공개 보호: 실제 요청 바이트 제한, API 호출 제한, 보안 응답 헤더를 적용하고 영속 호출 제한이 없으면 유료 AI 대신 기본 안내 제공
- 데이터 상태: 실제 완료 여정 0건, 파일럿 단계 `READY`

공개 데모의 HTTPS 배포와 실제 파일럿 운영 준비는 구분한다. 현재 배포는 체험에 적합하지만 실제 참여자료를 받는 운영 시스템은 아니다.

## 왜 나중에는 필요한가

| 요소 | 실제 서비스에서 필요한 이유 | 지금 미뤄도 되는 이유 |
|---|---|---|
| 관리형 PostgreSQL | 여러 참여자의 예측 잠금·동의 이력·탑승 결과를 동시에 보관하고 트랜잭션, 백업, 복구, 접근통제를 제공 | 현재 실제 파일럿 완료 0건이며 로컬 파일 저장으로 기능 시연과 테스트 가능 |
| 인증된 HTTPS 쓰기 API | 이동 중 개인정보·동의·익명 토큰 전송을 암호화하고 접근통제와 외부 콜백을 안정적으로 사용 | 현재 공개 배포판은 쓰기 API를 차단해 참여자료를 받지 않음 |
| 상시 운영 서버 | 공공 API 갱신, 예측 잠금, 현장 결과 입력, 운영 로그를 여러 기기에서 사용 | 현재 공개 데모는 핵심 흐름 체험과 읽기 전용 상태 확인에 집중 |
| 자동 백업·모니터링 | 파일럿 자료 손실과 장애를 방지하고 감사 가능성을 확보 | 실제 참여자료를 수집하지 않는 동안 운영 위험이 낮음. 공개 데모의 API 쿼터와 오류 상태는 계속 관찰 |

## 배포를 다시 P0로 올리는 조건

다음 중 하나가 생기면 배포를 즉시 우선순위로 올린다.

- 실제 파일럿 참여자 모집을 시작
- 기관 원장 대조나 다기기 현장 기록을 시작
- 운영기관과 실제 데이터 검증 범위·책임·보관기간을 합의

## 이후 권장 순서

1. 관리형 PostgreSQL 연결과 마이그레이션
2. 인증된 HTTPS 쓰기 API와 서버 비밀키 분리
3. 자동 백업·보존기간·철회 삭제 검증
4. 오류 추적·API 쿼터·상태 모니터링
5. 30건 파일럿 뒤 Brier·P50/P90 운영 성능 공개
